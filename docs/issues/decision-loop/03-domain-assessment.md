# 03 — 领域读数：技能分 + 区间

**What to build:** 用户问"我在**投资/宏观**上的水平如何"，拿到一个可解释的答案：以该领域基准率为参照的技能分、它的 bootstrap 区间、样本数（含悬空计数）、校准与分辨率；样本不够时只给样本数，不给结论。

**Blocked by:** 01（没有标签无法分桶）、02（悬空样本改变分母，必须先有正确的过滤）

**Status:** implemented（验证：`npm run typecheck` / `npm run lint` / `npm test` 全绿——**292 个用例**，其中领域读数 9 条（含三条自证：全押基准率 ⇒ 技能分恰好 0、固定种子逐位相同、顺序无关）；对等性门禁已把 `tags.domainReport` 判为**双侧可达**）

### 实现说明

- `lib/web/domain_stats.ts`：**纯函数**统计核心（不引 prisma），因此能被 `lib/web/fixtures/domain_samples.ts` 的合成样本直接钉住。一条题一个样本 = 该 Owner 已背书预测的均值（与 `_scoring.ts` 同口径）。
- 参照基准率由系统算（该前缀下已结算题的实际发生率），路径上**没有任何**能传进自报值的入口。
- 阈值与种子是代码常量：`N_MIN_FOR_BINS = 5`、`N_MIN_FOR_VERDICT = 20`、`BOOTSTRAP_ITERATIONS = 2000`、`BOOTSTRAP_SEED`。
- CLI `domain-report --prefix` + Web `/domains?prefix=` 页共享同一过程，页面不自己算任何数。

### 开发中抳到的两个真问题

1. **Brier 写错了**：我最初写成「预测值对其均值的偏差」，而 Brier 是 `(预测 − 实际结果)²`（参照策略才是 `(基准率 − 结果)²`）。fixture 里的「全押基准率」样本直接把它变成红色——这正是那份 fixture 存在的理由。
2. **我的断言太乐观**：n=24、技能分点估计 +0.44 时，bootstrap 区间下界是 −0.024 ⇒ **诚实结论就是“无法判断”**。ADR-0033 §四 的三种表述都要有用例覆盖，所以把“校准良好”那一支做成强信号（n=40、预测极端）。

### 一处 ADR 读法的确定（R1，业主裁定）

ADR-0032 §四 写着「N<20 不显示**曲线**与技能分」与「N<5 连**桶**也不显示」。这里的“曲线”指校准曲线的**图形呈现**（既有的 `components/CalibrationChart.tsx`，ChartJS），“桶”指其**数字**（分桶表）——两者在这个仓库里本来就是分开的呈现物（`CalibrationChart.tsx` 最后一次提交 `6643b6a`，早于本轮全部工作）。因此读法是 **R1**：**n≥5 给桶与分辨率（形状），n≥20 才给技能分与区间**；N<20 不渲染曲线。阈值卡的是**判据**，不是形状。已由业主确认，并在 ADR-0032 §四 追加了同义澄清句。

（早先本节写成“内部张力…只有一种自洽读法”，是过度断言：R2——认字面“只显示 N 与悬空计数”——在当时也是可读的，它被否掉靠的是本节上面那些事实，而不是“自洽”。）

### 已知缺口

- 读数只算**二元题**：选项级结果与题级发生率不是同一个量，当成一样算会得到一个没人能复算的数。这是有意留的口子，已写在过程注释里。

- [x] `domain-report --prefix 投资/宏观` 输出：`n`、`pending`（悬空计数）、校准分桶、分辨率、`skillScore`、`ci`、`brier`、`brierRef`、`verdict`（`better` / `worse` / `inconclusive`）
- [x] 参照基准率**只由系统计算**（该前缀下已结算题的实际发生率）；没有任何自报或可配置入口（ADR-0032 §二/§五）
- [x] 对每条题都押基准率时，技能分**必须为 0 且区间跨 0**（自证用例：去掉参照逻辑即变红）
      — `domain_stats.test.ts`；那个领域按构造 Brier == Brier_ref，把参照换成任何常数都会变红
- [x] `n < 20` 只显示 `n` 与 `pending`，不显示技能分与曲线；`n < 5` 不显示桶（ADR-0032 §四）
      — 实现为 n≥5 给桶、n≥20 给技能分（读法 R1，见票据里的“ADR 读法”一节）；阈值以下**字段不存在**，下游无从把噪音当结论展示
- [x] 报告注明"此读数包含其子标签的条目"（ADR-0030 §十三）
      — `includesDescendants: true` + CLI/Web 文案
- [x] 固定随机种子：同一份数据两次运行结果逐位相同（防 flaky，`retries: 0`）
      — 自实现 mulberry32；另有一条"输入顺序无关"用例（数据库返回顺序是不确定的）
- [x] 区间跨 0 时文案为"无法判断方向"，不含任何趋势性措辞（ADR-0033 §四/§六）
      — `verdictOf` 只由区间决定（不由点估计符号），Web 页三态文案各一句
