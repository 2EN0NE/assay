# 09 — 清单按"决策版本"计分

**What to build:** 条目集合加版本。新建决策记录它所属的**决策版本**，完成度按该版本的条目集合计算，界面也按该版本渲染。于是"后来删掉一条"不会让历史决策的分变好看，"后来新增一条"也不会让它掉下来。顺带删掉无人写、无人读的 `DecisionRubricEntry.note`。

**Blocked by:** 08

**Status:** implemented（验证：`npm run typecheck` / `npm run lint` / `npm test` 全绿；迁移 `20260913143221_decision_rubric_version`）

- [x] 条目集合是"版本 → 条目列表"的常量表；**既有版本的条目列表不得改写**，增删只能新建一个版本（测试钉住：改写既有版本会被测出来）
- [x] 新建决策记录 `rubricVersion`；写入清单只接受该版本的条目键，未知键被拒且一行不写
- [x] 完成度 = 该决策**所属版本**内"做到项数 / 条目总数"，与当前代码版本的条目集合无关
- [x] 详情页按该决策的版本渲染条目：删掉一条后，历史决策仍显示当初那 5 条与它们的完成情况
- [x] `DecisionRubricEntry.note` 从 schema 与迁移中删除（无写入方、无读取方）

> **如实说明**：条目集合目前只有一个版本，所以“按决策自己的版本”与“按当前版本”在**行为**上暂时无法区分；钉住这件事的是两处——版本表被整张测试锁住（改既有版本就红），以及 `deriveRubricCompletion` / `validateRubricEntries` 强制要求传入版本。
