# 决策质量记成"可查证的过程清单"，而不是自评分

决策质量以**过程检查清单**记录（`C` = ②），辅以叙事文本（③），不采用自评量表（①）。将来若要一个可比较的分值，**由清单完成度推导**（例如 5 项做到 3 项），而不是让当事人给自己打分。

为什么不自评（①）：本系统刚刚为了防 `Compliance Number` 给追问设了显式出口（ADR-0010、ADR-0011），而一个 1–5 分的自评**恰恰就是一个新的敷衍数字**——同一系统里一边防敷衍、一边开新的敷衍入口。更根本的是它**不可查证**：3 分与 4 分的区别无人能复核。

为什么清单更好：它的每一条都是**可查证的事实**（"有没有写下备选方案"），契合"可观测、可验证是首要前提"；且**诊断力更强**——清单告诉你**漏了哪一步**，一个分值什么也不说。

为什么保留叙事（③）：复盘时它是唯一能还原"当时为什么这么想"的材料。

**层归属（修正）**：这张清单是**决策质量层**的追问脚本，与**预测捕获层**的追问脚本（ADR-0010 的概率 / 期限 / 判据）是**不同层的两件事**，不是同层的两套问法。

初稿曾写"这张清单就是 `J` = ① 的追问脚本，两个决策合并成一个机制，不需要两套"。它与 ADR-0010 直接冲突：ADR-0010 把 `J` 的终止条件定为"拿到概率、期限与判据"，而清单五条里只有"判据可证伪且已冻结"一条与之重合，另四条（备选方案 / 事前剖析 / 参考基准率 / 我可能错在哪）既不在那三项之内，也不包含那三项。正确关系是分层：

- **预测捕获层**（Phase 1，`SKILL.md`）：问出概率 / 期限 / 判据，使 Prediction 可结算、可校准；终点由 ADR-0011 定义。
- **决策质量层**（Phase 2，随 `Decision` 表）：问出清单四条，记录**过程**；终点是清单走完。

两层共用同一个对话时机（都在"决策当时"，见 ADR-0009），但**清单不进 Phase 1 的 skill**：清单的价值在于被**记录**（"需记录每条清单项的完成情况"），而记录需要 Phase 2 的表与复盘视图。只问不存既拿不到诊断价值，又白付 ADR-0009 已承认的"打扰"代价——每条约七问的审讯感会直接推高 `Compliance Number` 的概率，也就是 ADR-0010 点名的那个危害。

## Considered Options

- **① 结构化量表评分**：最易变成随手填的数；只有好坏，没有"错在哪"。
- **③ 仅叙事文本**：信息最丰富，但不可比较、易事后美化。

## Consequences

- 初始清单条目（可增删）：备选方案 ≥ 2；事前剖析；参考基准率；写下"我可能错在哪"；判据可证伪且已冻结。
- 清单在**决策当时**填写——那时还没有后见之明可以污染它。
- 需记录**每条清单项的完成情况**，而非只存一个总分。
- Phase 2 的"决策量表（Decision Rubric）"改为**由清单条目构成**，而不是另立一套分值维度表。
- **分层落地**：`SKILL.md`（Phase 1）只含概率 / 期限 / 判据三项追问；清单四项随 Phase 2 的 `Decision` 表一起进，与其记录能力同时交付（见上「层归属」）。
