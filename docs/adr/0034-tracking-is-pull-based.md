# 跟踪由拉取驱动：提醒载体只有 AGENTS.md 与 skill，不做任何 harness 专属物

ADR-0013 定了"站内是唯一内置通道"，ADR-0017 定了拉取式。实现层的事实是：

- 通知行**确实会被创建**（`lib/web/agent_router.ts` 的 `notify()`），但**没有任何东西把它推进 agent 会话**。
- CLI 已有 `list-due` / `list-deliveries`。
- `skills/` 里原先只有一个**捕获**技能 ⇒ "跟踪"这一半没有 agent 侧指令。用它的人必须自己想起来问一句"有什么该结算了"。

本 ADR 补上这一半，并顺带钉死一件事：**提醒不靠任何绑定在某个 agent 运行时上的东西。**

**本 ADR 修正 [ADR-0006](./0006-tracking-triggers.md) 的实现载体。** ADR-0006 把“定期全量巡检”列为**必选**触发条件之一，但对“谁在跑这次巡检”只留了个调用约定（它自己写明“具体周期是细节，见 roadmap”）。本 ADR 回答的正是那一条：巡检的载体**不是**计划任务、cron 或常驻进程，而是**会话开始时的一次拉取**。

触发时机（到期 + 定期）不变，**收窄的是载体**；代价是“没人开会话就没有巡检”，这是 ADR-0017 选拉取式时就已接受的代价，换来的是不依赖任何进程活着（见下面第三条）。ADR-0006 列的三个洞（提前确定、无期限、逾期）仍然由会话开始的那次拉取兜住——只是它不再由一个独立的定时进程驱动。

**一、提醒只有两个载体，都是中性的。**

1. `AGENTS.md` 里一句：**会话开始时先拉一次到期队列**。`AGENTS.md` 是跨 harness 的公共约定（pi、Codex、Cursor 等都读它），不绑定任何一家。
2. skill 里写触发条件：**涉及决策、复盘、到期时先拉**。

**二、不提供 pi 扩展、Claude hook、cron 脚本、常驻守护进程。**
交付面就是 CLI + skill（外加给人看的 Web）。任何只在一个运行时里能用的东西，都会把"这套东西能不能用"重新绑回那个运行时——而 skill 格式存在的全部理由就是避免这件事（AGENTS.md §8 的 harness 中立是同一条主张）。

**三、拉取式是设计，不是缺陷。**
ADR-0017 已经选了它，而它还有一个实际好处：提醒**不依赖任何进程活着**。没有东西需要被后台守护、没有推送凭证要管、没有"提醒没到是因为服务挂了"这一类故障。

**四、提醒有上限，否则等于没有。**
只报**计数**，外加最多 **3 条**最近的到期项；不阻塞对话、不在每次回复里重复。一条被忽略的提醒和不存在没有区别，而重复到被忽略只需要几次。

**五、到期队列必须区分两种"没结算"。**

| 状态           | 含义                     | 判定                                 |
| -------------- | ------------------------ | ------------------------------------ |
| 可结算         | 到点了，有人能核实       | 存在可核查来源，或它就是你的自我报告 |
| **悬空未结算** | 到点了，但**没人能核实** | 只有他人的无来源确认（ADR-0031）     |

混在一起会让人读成"我还没去结算"，而事实是"这条没法定论"。前者是待办，后者不是。

## Considered Options

- **站内通知推送进会话**：需要常驻进程与"当前用哪个 harness"的知识 → ADR-0013 已排除，且违反本 ADR 二。
- **写一个 pi 扩展，在会话开始时自动拉取**：体验最好 → 但它把可用性绑回 pi；使用者换成别的 agent 时这套东西就静默失效，而"失效"不会报错。
- **cron / 定时脚本**：不绑 harness → 但绑一台**常开的机器**，且它没法把结果送进任何会话（绕回推送问题）。
- **邮件提醒**：不绑 harness、不绑机器 → 引入一套需要维护的邮件凭据与投递链路，而"我该结算了"这件事的价值远低于它的维护成本。

## Consequences

- **CLI**：`list-due` 输出分"可结算"与"悬空未结算"两栏（后者附成因）。
- **skill**：新增一个跟踪技能，描述"拉队列 → 带来源直接结算 → 无来源提提案 → 等用户确认"这一回路。
- **`AGENTS.md`**：加一行会话开始拉队列的指令，并写明提醒上限（计数 + 3 条）。
- **测试**：一条自证用例——悬空项**不得**出现在"可结算"栏（去掉分流即变红）；skill 的 frontmatter 与目录名一致性由既有校验覆盖。
- **明确不做**：任何 harness 专属扩展、cron、守护进程、外部推送通道。
