# 结算生效范围按可核查性分叉：公共事实谁确认都算，其余只对确认者生效

ADR-0029 定了"结算授权按 Forecast 的 Owner"，并留下一个开放项：**一条题被一个人确认后，其他人是否被代签**。改了 `decide-proposal` 的授权（票据 07）之后立刻会撞上它。

先列三个已核实的事实：

- `Question` 上**已经有 `oracleKind`**，ADR-0029 的三类（公共事实 / Agent 可观测 / 自我报告）在数据层已存在。
- 今天 `decide-proposal` 只允许**出题人**接受（`agent_router.ts:465` 以 `question: { userId: ctx.userId }` 过滤）——与 ADR-0029 不一致，票据 07 改。
- 库里**没有任何字段记录"结算是谁确认的"**。

**一、把"授权"与"生效范围"拆成两个独立问题。**
ADR-0029 回答的是**谁有权确认**；本 ADR 回答的是**确认之后约束谁**。混在一起会让"Agent 可观测"这类情形无从判断。

| 情形                       | 谁有权确认（ADR-0029） | 生效范围（本 ADR）                                   |
| -------------------------- | ---------------------- | ---------------------------------------------------- |
| 公共事实，**带可核查来源** | 任何身份               | **所有**在该题上押过注的 Owner 都被计入              |
| Agent 可观测，**带来源**   | 该 Owner               | 同上（来源可被复核，数字是客观的）                   |
| 自我报告 / 无可核查来源    | **只能本人**           | **只有确认者自己**被计入；其他人的 Forecast **悬空** |

判据只有一条：**结算记录有没有可核查来源。** 有 ⇒ 它陈述的是事实，你点不点头都不改变事实；没有 ⇒ 它陈述的是某人的判断，不得替别人签字。

**二、悬空是合法状态，而且必须可见。**
被悬空的 Forecast：**不进校准、不进任何分数**，但**仍然出现在复盘与清单里**，显示为"未结算（无可核查来源）"。让"没有计量"和"没有这条预测"在复盘时不可区分，才是真问题。

**三、"谁确认的"必须落库。**
结算记录上记确认者（一格）。它服务审计（ADR-0027）、呈现（"由他方确认结算"）以及下面那条计量规则。

**四、不做"全体确认"。**
看着更公平，实际后果是：只要有一个受影响 Owner 离线或遗忘，这条题**永久悬空**——一个没人能关闭的状态会让整条数据链停住。悬空应当由"来源缺失"产生，而不是由"有人没上线"产生。

**五、补录来源即可解除悬空，不需要投票。**
后来出现了可核查来源 ⇒ 把来源补上 ⇒ 该题上所有预测生效。这不是"撤销结算"，因此不触碰 ADR-0020 的锁定单向性。

**六、计量过滤规则（守门的对象）。**
一条 Forecast 计入计量，当且仅当：

```text
question.resolved && (resolution.source != null || forecast.userId === resolution.confirmedBy)
```

这条规则要有一条"去掉守卫即变红"的用例：无来源、由他人确认的结算，**不得**进入被代签者的校准。

## Considered Options

- **(a) 任一受影响 Owner 接受即全体生效**：最简单、库里什么都不用加 → 但别人代你签字，你的校准里静默混进你没确认的结算。这与 ADR-0028 锚定保护是同一种病：**别人替你决定你看到什么、信什么**。
- **(b) 全体受影响 Owner 必须确认**：没人被代签 → 但离线即永久卡死；且它对"公共事实"这类客观结果也强加了不必要的仪式（一张你无法反驳的事实表也要你签字）。
- **(per-question, per-user) 确认状态表**：语义最直白 → 多一张表 + 一套状态机，而上述一条过滤规则已经能达到同样效果，且悬空状态可以**推导**而不是存储。

## Consequences

- **schema**：结算记录加 `confirmedByUserId`（一格）。**实现前须核实**：直接结算路径（`agent_router.ts:392` 判 `oracleKind === "PUBLIC_FACT" && source !== undefined` 时）**是否真的把 `source` 落到库**——若没有落库，本 ADR 的判据就无从判断，得先补上。
- **计分**：过滤规则落在校准/计分入口（`getBucketedForecasts`、`QuestionScore` 一侧），不是落在呈现层。
- **CLI**：`list-due` 与复盘要能区分"未结算"与"悬空未结算"，并给出成因（来源缺失）。
- **测试**：四类用例——带来源他人确认（计入）、无来源他人确认（**不计入**）、无来源本人确认（计入）、悬空后补来源（计入）。
- **不做**：per-user 确认状态表、任何形式的结算投票、以及"撤销题级结算"的回退路径。
