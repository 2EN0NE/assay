# 跟踪 Agent 的结算权限按判据类型分层

跟踪 Agent 的结算权限取决于 `Prediction` 的**结算判据类型**：

- **公共事实**：可自行结算，**但必须附可核查的来源**；无来源则降级为提案。
- **Agent 可观测**：只能提交 `Resolution Proposal`，由用户确认。
- **自我报告**：必须由用户本人报告，并对照决策时冻结的评分锚点。

授权尺度的依据与 ADR-0002 同源：**判据离当事人越远，可授予的自主权越大**。公共事实有客观来源，自行结算不引入漂移且免于打扰；自我报告结构上不可授权——没有人能替你判定你满不满意；Agent 可观测是灰区，同一信号可有多种解释，因此只能提案。

"公共事实类无来源即降级为提案"是硬约束：独立上下文意味着没有人能当场纠正 Agent 的幻觉。若允许它无证据自行结算，一个编造得很确定的 YES 会直接进入校准数据。

## Considered Options

- **① 仅提案**：所有结算都要用户确认 → 用户被反复打扰，遗忘即烂尾。
- **③ 全权**：Agent 结算一切 → Resolution Drift 并未消失，只是从当事人转移给了 Agent。

## Consequences

- 领域模型需要区分**结算提案（proposed）**与**已结算（settled）**两种状态。
- 每次自行结算必须携带 `Evidence`（可核查来源），否则不得生效。
- 跟踪 Agent 需要一个面向用户的**确认入口**（Web 或对话）。
- `Evidence` 落库在 `Question.resolutionSource` / `Question.resolutionRationale`：自行结算时由 `agent.settle` 写入，提案被采纳时从 `ResolutionProposal` 复制——站内通知只是同一条记录的投影，不是唯一的存储处。
