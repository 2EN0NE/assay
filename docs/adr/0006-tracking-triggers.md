# 跟踪由到期触发与定期巡检共同驱动，事件驱动只传证据

跟踪调用由三种条件发起，其中两种为必选：

- **到期触发**（必选）：`Prediction` 的 `resolveBy` 到达时发起。
- **定期全量巡检**（必选）：固定周期扫描所有**未结算**的 `Prediction`，兜住逾期、漏网与无明确期限的预测。
- **事件驱动**（可选，受限）：对话或外部信号出现时发起，但**只允许传入可核查的证据（链接 / 观测事实），不得传入记录时的推理与结论**。

到期触发保证"记录过的预测一定会被结算"——不设它，预测会烂尾，这是这类系统最常见的死法。定期巡检补上两个洞：公共事实常常早于期限就已确定（早结算才能早闭环），以及无期限 / 逾期的预测。

事件驱动最诱人，也最危险：它正是 ADR-0003 要防的那件事——把记录时的语境送回结算。之所以仍保留它，是因为"你刚聊到这件事"是价值最高的触发时机。约束（只传证据、不传推理）**不是可选的礼貌，而是 ADR-0003 隔离要求的直接推论**：跟踪 Agent 必须能独立复核。

## Considered Options

- **仅到期触发**：漏掉提前确定、无期限与逾期的预测。
- **禁用事件驱动**：隔离最彻底，但失去价值最高的触发时机。

## Consequences

- 跟踪的调用入口需要接受一个**证据**参数，而不是"结论"参数。
- 需要一个定期巡检的调用约定（具体周期是细节，见 roadmap）。
