# 记录与跟踪分离，跟踪委托给独立上下文的 Agent

**记录（Recording）**在决策时点发生，由与用户对话的 Agent 完成，只负责把 `Decision` 与 `Prediction` 固化为**可独立结算**的记录。**跟踪（Tracking）**在决策之后发生，由**独立上下文**的 Agent 完成，负责监测与结算，且**不得依赖记录时的对话上下文**。

分离的原因是结构性的：如果同一个上下文既记录又结算，它在结算时会"记得"当初的讨论，于是把事后解释当成当初的判断——这正是 **Resolution Drift** 的来源。独立上下文逼着我们**在记录时就写出全部结算所需信息**（判据类型、结算标准、锚点、期限），否则跟踪 Agent 无从下手。

## Consequences

- Recording 必须产出"无需回问记录上下文即可结算"的记录。
- 跟踪侧的"独立上下文"由 pi harness 提供，不需要自建运行时（见 [ADR-0005](./0005-tracking-as-plain-pi-invocation.md)）。
- 两个 Agent 通过持久层通信，不共享上下文。
