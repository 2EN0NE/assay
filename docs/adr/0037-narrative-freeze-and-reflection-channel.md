# 决策叙事在揭晓后冻结；事后表达走独立、只增不改的复盘记录

[ADR-0016](./0016-decision-quality-as-checklist.md) 拒绝「仅叙事」方案的理由之一是「易事后美化」。而 [ADR-0020](./0020-decision-rubric-storage-and-lock.md) 第五点又明确让叙事成为结算后**唯一**可写的那一半：「清单锁定后只读（服务端拒绝），叙事字段仍可补充——叙事不被评分，事后补充它不产生激励扭曲。」

这个不对称当时是有理由的（叙事不进分值，所以补它不影响分）。但它有一个从未被检验的前提：**「事后写的」与「当初写的」看得出来**。这个前提不成立：

- `lib/web/revisions.ts` 的 `planNarrativeRevisions` 对「空白 → 填写」直接跳过——**补写不产生 Revision**，因此没有旧值、没有理由、没有时点。
- 于是一个字段如果在决策当时是空的，事后填进去的内容在库里与「决策当时写下的」**完全同形**。
- 现实里这条路径已经被走过一次：会话中建议「用 `update-narrative` 记一条复盘笔记」。那次**侥幸**留了痕，因为五个字段恰好都非空，改动必须带 `--reason` 从而生成 Revision——留不留痕取决于「字段是否恰好非空」，不取决于任何规则。

也就是说：系统一边以「易事后美化」为由拒绝仅叙事方案，一边把这条路留着，且**无制衡**。

**一、冻结与清单用同一个判据、同一个函数。**
判据仍是 ADR-0020 第五点的「事实 ∨ 已记录的时点」：该决策下存在已结算的 Prediction，或 `lockedAt` 已有值。实现上是**同一个纯函数**（现名 `rubricLockOf`，本 ADR 改名为 `decisionLockOf`），只是从管一个对象变成管两个。

**二、冻结包含空白。**
揭晓后，五个叙事字段（陈述 / 理由 / 预期后果 / 当时已知 / 当时未知）**连同它们的空白**一并只读。冻结时是空白，就永远是空白。

这条看似损失，其实是收益：**空白本身是记录**——它说的是「当时没记」。事后填进去一段看起来像当时的文字，比留一个空更难还原真相。

**三、事后表达走 `DecisionReflection`：独立、只增、不可改、不可删。**
每条带 `createdAt`，与叙事字段**物理分开**：不必读时间戳就知道它是事后的。它不参与任何分值，也不冒充当初的想法。

选「只增不改」而不是「一条可编辑的复盘字段」，是因为后者会把同一个病挪个位置：**后来的复盘盖掉前面的复盘**，而覆盖同样无声。ADR-0012 的立论是「危险来自无声」，append-only 让它**没有无声的可能**，于是复盘不必为每次改写编一个理由——复盘的摩擦应当越低越好。

**四、`reflection` 不设时机门槛。**
任何时刻可写。[ADR-0011](./0011-unquantified-predictions.md) 明确「一个决策可以 0 条预测」，而**放弃一个决策**正是最该复盘的时刻；若门槛写成「揭晓后才能写」，那种决策永远无法复盘。

它不需要门槛来防冒充：它永远不冒充「当初」。渲染时把每条相对揭晓时点的位置**派生**标注（写于揭晓之前 / 之后），冒充没有收益。

**五、写入侧直接拒绝，不靠理由拦。**
`update-narrative` 在冻结后返回 `CONFLICT`，文案指向 `record-reflection`。（当前实现的「改写非空字段必须带 `--reason`」在冻结后**不再适用**——因为任何改写都不允许，而不是"允许但需理由"。）

**六、为什么不是「给叙事加一个事后写入标记」。**
最省事的方案是加一个决策级时点（与 ADR-0020 第六点的 `rubricRecordedAfterOutcomeAt` 对称）。它的缺陷是**粒度错配**：标记是**决策级**的，而混同是**字段级**的——标记只能告诉你「本决策有事后补写」，不能告诉你「就是『当时未知』那一栏」。于是下一个读这条记录的 agent（半年后拿到 `show-decision` JSON 的那个）仍然会引用一句它以为是当初写下的话。

要把标记做到够用，就得逐字段（5 个可空列或一张写入表），那时的成本与本 ADR 相当，而本 ADR 还多得到一条：**叙事与清单的时机口径对称了**（两者都在揭晓时冻结，各有各的显式事后通道——清单没有，叙事有 `reflection`）。

**七、代价。**

- **订正做不到了。** 陈述里写错标的代码、判据里错别字，冻结后只能写进 `reflection`，或者手工改库（ADR-0020 Consequences 已承认这条路径存在且不留痕）。本 ADR 的口径是：**订正与美化在系统眼里是同一个动作**，于是两者一起关掉。
- **空白永久。** 见第二点，这是目的。
- **多一张表、一条命令、两个表面的入口。**

## 修正了谁

- **本 ADR 修正 [ADR-0020](./0020-decision-rubric-storage-and-lock.md) 第五点的这一段**：「清单锁定后**只读**（服务端拒绝，`CONFLICT`），**叙事字段仍可补充**——叙事不被评分，事后补充它不产生激励扭曲。」——**"仍可补充"不再成立**：叙事在揭晓后与清单一同冻结；「现在回看，我当时低估了什么」这类补充改由 `reflection` 承载（它仍然可行，只是不再写进原字段）。
- **本 ADR 收窄 [ADR-0012](./0012-revisions-must-leave-a-trace.md) 的例外句**：「**给空白字段补写不受此限**：那不是改写，而是当初就没记。」——该例外对 **Decision 叙事字段**收窄为「**揭晓前**自由；揭晓后连空白一并冻结」。Question 的冻结字段（判据 / 期限 / 锚点）不受本 ADR 影响，仍按 ADR-0012 原样。
- **本 ADR 修正 ADR-0020 第五点的字段名**：`Decision.rubricLockedAt` → `Decision.lockedAt`。理由不只是它现在管两样东西：那个值写入的是**观察到的时点**（结算路径上取 `now()`，通常略晚于 `resolvedAt`），而不是揭晓时点本身，所以叫 `lockedAt` 才是它在说的事。

## Considered Options

- **决策级「事后写入」标记**（与第六点对称）：最小改动 → 粒度错配，只能披露到「有」、披露不到「哪一段」（见第六点）。
- **逐字段标记**（5 个可空列）：披露到位 → 成本追上本 ADR，且仍要维护「这条标记与 Revision 谁是权威」的第二种真相。
- **F′：冻结 + 允许"无争议字段"的订正**（错别字、代码、日期）：保住可订正性 → 但"无争议"只能由人判断，系统无从复核；它把结构保证换成一个自觉。
- **结算后叙事完全不可写、也不加 `reflection`**：最干净 → 复盘材料彻底没了，而「现在回看」正是最有价值的那一半。
- **复盘也走 `Revision`**（把复盘当改写）：复用现有留痕 → 每次复盘都要编一个 `--reason`，摩擦随次数上升；而且 Revision 描述的是"改了什么"，不是"现在怎么看"。

## Consequences

- **schema**：`Decision.rubricLockedAt` 改名为 `lockedAt`（手写 `RENAME COLUMN` 迁移，不得退化成 `DROP + ADD`——那会静默丢值）；新增 `DecisionReflection { id, decisionId, body, createdAt }`（`@@index([decisionId])`，**不加** `updatedAt`：它不可改，加了就暗示可改）。
- **迁移验证**：`scripts/verify-migration-upgrade.ts` 必须补一条断言——迁移前后每条 Decision 的锁定时点**值与存在性不变**。CI 在空库上跑，看不见这个。
- **纯函数**：`rubricLockOf` → `decisionLockOf`、`RubricLock` → `DecisionLock`；新增「相对揭晓时点」的派生标注。
- **命令**：新增 `record-reflection`（CLI + Web 两个表面，`cli/parity.test.ts` 会拦）；`show-decision` / `decision.byId` 返回 `reflections`。
- **复盘视图**：叙事 + 清单为一栏（当初的记录，标注冻结时点），`reflection` 为另一栏（事后，每条带时点）。两栏并列而不合并——与"决策与结果并排"是同一条理由。
- **skill**：`decision-capture` 写明「事后表达走 `record-reflection`」；`settlement-tracking` 写明「结算即冻结叙事，结算前的最后机会」。
