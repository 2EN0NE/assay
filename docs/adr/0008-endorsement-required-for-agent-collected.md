# 未经当事人背书的 Agent 搜集记录，不得进入校准

由 Agent **自主搜集**（`Provenance` = agent-collected）产生的 `Prediction`，在当事人明确**背书**（确认那个概率数字）之前，不得计入 Brier 校准。未背书的记录仍保留在系统中、可被展示与复盘，但**不作为校准样本**。

理由是校准的语义：校准是"你 vs 你的过去"的对话，不是"你 vs Agent"的对话。若样本里混入当事人从未认同过的概率，那条校准曲线就同时在测两样东西，于是两样都测不准。相对分（ADR-0002）同理且更严格——它要求多个预测者对同一命题下注，而未经背书的数字连"下注"都算不上。

**数字由当事人给出**的记录（`Provenance` = `AGENT_INSTRUCTED`）天然被背书，不受此约束。判据取"**数字的来源**"，而不是"当事人是否下过一条明确指令"——这两者会分歧，而唯一与目的（校准样本必须是当事人真正认同过的概率）直接对应的只是前者：当事人**随口**说出的"我大概七成把握"同样是他的信念，只是没人下过指令；反之，Agent 自己从别处取得或推演出的数字，即使产生在对话里，也从未被当事人认同过。

## Considered Options

- **① 一律计入**：让 Agent 的猜测冒充当事人的信念，污染唯一能反映校准度的数据。
- **③ 单独展示、永不进校准**：最保守，但使这类记录永远无法转为有效校准样本——它们本可在背书后使用。

## Consequences

- `Prediction` 需要一个"是否已背书"的状态；agent-collected 记录默认未背书。
- 复用 ADR-0004 的"提案 → 确认"机制收集背书，不引入新概念。
- 与"决策捕获的触发"（roadmap `I`）强耦合：若不允许自动识别，此类记录几乎不产生。
- `Provenance` 取 `HUMAN` / `AGENT_INSTRUCTED` / `AGENT` 三值：`AGENT_INSTRUCTED`（数字由当事人给出）创建时即 `endorsed = true`，不进未背书队列；只有 `AGENT`（Agent 自己取得）默认未背书。
- **危险情形必须由调用方显式声明；安全情形不要打勾。** 接口无法自行分辨"这个数字是不是当事人说的"，因此 `createPrediction` 的默认值是"数字来自当事人"（`AGENT_INSTRUCTED` / 已背书），Agent 自己取得的数字必须显式声明——CLI 用 `--agent-collected`（`lib/web/agent_router.ts` 的 `createPrediction`）。

  这条例外的方向是刻意的：本 ADR 要防的危害是"当事人从未认同的数字混进校准"，不是"当事人的数字被拦住"。若把显式开关给安全情形（早期实现里的 `--instructed`），忘记打勾就会把当事人的数字静默拦在校准之外，且**没有任何症状**；更糟的是未背书队列会因此常驻假警报，而队列里唯一的动作是"背书"，于是背书退化成橡皮章——等真正的 `AGENT` 样本出现时它已经不値钱了。所以宁可让危险情形承担"多打一个标志"的义务，并让这个标志本身可 grep、可测（`lib/web/agent_router.test.ts` 锁定 polarity，因为反转错了不会产生任何症状）。

- 背书发生在结算之后时，必须**重算**该问题的分数（`rescoreResolvedQuestion`）——否则界面上"尚未背书"消失，校准里却永远没有这一笔，且没有任何症状。
