# 「从未记录」不是「没做到」：清单读数区分缺失与否定，可派生的事实只披露、不计分

[ADR-0016](./0016-decision-quality-as-checklist.md) 把决策质量记成一张**可查证的过程清单**，理由之一是「清单告诉你漏了哪一步」。实际用起来，这个诊断力被一个同形问题吃掉了：

- 清单的完成情况是**逐条记录**的（`DecisionRubricEntry`）。没记录的条目在库里不存在。
- 但完成度把它与「记录为 `NOT_DONE`」折进同一个 `missing` 数组（`deriveRubricCompletion`）。
- 于是复盘视图里，`0/5` 有两种完全不同的成因，长得一模一样：**一步都没做到**，与**一步都没记**。

真实案例：一条决策结算时 `rubric = 0/5`、`rubricEntries = []`，而它的一条预测的判据恰好「写死了、从未改过」——一个**事实成立**的过程步骤，在记录里与「没做」不可区分。当事人看到的是两个负面读数（Brier 0.72 与 0/5），而他"其实做对了的那一步"没有任何位置。

**一、三态由缺失派生，不落库。**

| 呈现                 | 来源                         |
| -------------------- | ---------------------------- |
| 做到（`DONE`）       | 有记录且 `status = DONE`     |
| 没做到（`NOT_DONE`） | 有记录且 `status = NOT_DONE` |
| **未记录**           | **没有这一行**               |

第三态是**缺失**，不是第三取值。`rubricStatusOf` 本来就已经返回 `undefined`（`decision_rubric.test.ts` 钉住了这一点），本 ADR 只是拒绝在呈现层把它折成第二态。

**二、完成度口径不变，叙述分开。**
分母仍是该决策版本的条目集合；**未记录与 `NOT_DONE` 都计入"漏"**（分子不变）。但返回与文案要把两者分开报：`missing`（记了没做到）与 `unrecorded`（从未记）。理由：前者是「知道该做但没做」，后者是「没记」，**对策不同**——前者要改做法，后者要改记录习惯，而后者在系统里根本没有提醒。

**三、`falsifiableCriteria` 不从库里推导计入分值。**

它看起来最可推导（判据是否写死、是否被改过）。但一个事实让它失去意义：

```
lib/web/agent_router.ts:286
resolutionCriteria: z.string().min(1, "结算判据不能为空：判据必须可证伪（ADR-0002）")
```

**判据是创建预测时的必填项。**于是「该决策下有一条判据非空且自创建起未被修订」几乎对**任何有预测的决策**都成立——它不是一条会失败的条目，而是 schema 强制出来的别名。把它推导计入，等于往分母里塞一个恒真项：

- 它不携带区分力，而清单的全部价值就在区分力（诊断力）。
- 它给分值安排了**第二个写手**（记录与推导），而 ADR-0020 第三点整套结构（不落库、按决策版本推导）是围绕「唯一写手 = 记录」建的。

恒真项的正当处理是**版本演进时删掉它**（ADR-0020 第四点：条目增删必须新建版本），而不是让它继续占分值名额。本 ADR 只记下这个将来项，**不在本轮做**：历史决策仍按 v1 的 5 项解释，所以新建版本救不了那条已经冻结的记录。

**四、读取侧派生注记：披露「库里能核到什么」，不算分。**
复盘视图在 `0/5` 旁边给出派生注记：

> 「判据可证伪且已冻结」：该决策下 1 条预测的判据自创建起未被修订（派生自库，**不计入完成度**）。

措辞有一条硬约束：它说的是**证据**，不是**评价**。写成「你做到了」就变成了偷偷的推导计分（第三点已拒绝）；写成「库里能核到这些」才对——当事人自己判断那算不算做到。

**五、写入侧提示，不代填。**
在能核到的事实出现时（挂接一条带判据的预测之后）提示「这条似乎已成立，要记下来吗」，仍由人或 agent 显式写入。**代填会造出第二个写手**，与第三点同一条理由；而完全不提示，就回到了「漏记 = 漏做」的起点。

**六、Q5 的代价被正式承认：清单只问「做没做」，不问「做得好不好」。**
「这步达到标准了吗」（基准率是否可核对、事前剖析是否成段）常常**在决策当时判断不了**；等判断得了，门已锁（ADR-0020 第五点）。本 ADR 的口径是：清单的每一条都是**存在性**事实——有没有写下备选方案、有没有写事前剖析。存在性在决策当时可知，因此清单可以在决策当时判；质量标准不可知，因此**故意不问**。

## 修正了谁

- **本 ADR 澄清 [ADR-0020](./0020-decision-rubric-storage-and-lock.md) 第二点**：「每条只有『做到 / 没做到』，没有『不适用』。引入 N/A 会立刻产生一个自我开脱的口子。」——**记录的取值**仍然只有二值，本 ADR 不改它；澄清的是：**「从未记录」不是第三种取值，而是缺失**。它与 N/A 的区别是本质的：N/A 是一个**声称**（"这段决策不需要事前剖析"），缺失是一个**事实**（"没有这一行"）。前者自我开脱，后者只是没记。
- **本 ADR 补充 [ADR-0016](./0016-decision-quality-as-checklist.md) 的一条 Consequences**：「需记录**每条清单项的完成情况**，而非只存一个总分。」——补一句：**没记 ≠ 没做**。缺少记录时，读数必须说"未记录"，不得读作"没做到"。

## Considered Options

- **推导计入分值**（`falsifiableCriteria` 自动为 `DONE`）：能让那位当事人的记录立刻变好看 → 但恒真项不携带区分力，且给分值引入第二个写手（见第三点）。
- **引入 `N/A`**：允许当事人说"这条不适用" → ADR-0020 第二点已拒绝，本 ADR 重申：它是自我开脱的口子，而且不可查证。
- **只在 Web 上分三态、CLI 不分**：改动最小 → 两个表面会说两套话，而 CLI 是 agent 取数的地方——恰恰是"弱模型照着读"的那一侧最需要它准。
- **未记录不计入分母/不报为漏**：看起来对当事人更宽容 → 但记录的完整性就失去压力，漏记重新变成无成本行为。
- **本轮就新建 v2 条目集合删掉该条**：治本 → 历史决策仍按 v1 解释，救不了已冻结的记录；而条目演进需要单独一次决定，不与本次披露修复捆绑。

## Consequences

- **纯函数**：`deriveRubricCompletion` 返回 `{ done, total, missing, unrecorded }`；`missing` 的语义收窄为「记了没做到」——所有消费方（CLI、Web、测试）随之调整。
- **派生注记**：新增一个纯函数，按该决策下各 Prediction 的 `resolutionCriteria` 与 `Revision`（`field = resolutionCriteria`）算出「可核到的事实」，返回 `{ itemKey, evidence }`，**不带分值**。
- **写入侧提示**：`attach-prediction` 的返回带上可核到的条目（若此时清单尚未冻结）。
- **两表面**：Web 决策页把 `⬜` 拆成「未记录 / 记了没做到」；CLI `show-decision` 的 `rubric` 带两个数组。
- **Q8 一并处理**：`premortem` 的展示文案改成显式时机（如「事前剖析（下注前写下会怎么失败）」）。按 ADR-0020 第一点，条目**存稳定标识而非文案**，所以文案改写**不需要新建版本**；但那张被逐字钉住的测试表必须被**有意地**更新。
- **本轮不做**：v2 条目集合（删掉/替换 `falsifiableCriteria`）。触发条件：下一次需要一个真正可失败的条目时，一次性随版本演进一起做。
