# 领域归属：权威在 Decision，写入时复制到 Question，之后不跟随

ADR-0002 把评估按**预测**分层。但用户真正要问的是"我在这类决策上的水平如何"——这句话的主语是 **Decision，不是 Question**。于是要先定：领域标在哪一层？标完之后，它与已有的"按 Question 标签分桶"的读数通道（`pages/api/calibration_graph.ts` 的 `getBucketedForecasts(userId, tags)`，上游 fatebook 的 `Tag` 机制）又是什么关系？

**一、领域是用户概念，标签是机制载体，两者不是同义词。**
用户说"领域"，指的是"招聘、投资、产品取舍"这类**他心里的分类**；系统里落的是一行 `Tag`（`@@unique([name, userId])`）。混用这两个词，会让后面所有文档在"要不要给 Decision 加领域字段"这类问题上失去判断力。术语落在 [CONTEXT.md](../../CONTEXT.md) 的"评估"节。

**二、权威在 `Decision`。**
用户表达一次"这条决策属于哪个领域"，而不是为它的每条预测各表达一次。一条决策挂三条预测就要求打三次标签，实际后果是**漏打**——而漏打的样本会静默地少掉，分桶曲线因此不是"少一点"，而是"偏一点"。

**三、写入时复制。**
挂接一条 Prediction（即一条 Question）时，把该 Decision **当时**的领域复制成这条 Question 的标签关联。

- 分桶查询**零改动**：它读的仍是 `Question.tags`，上游机制与现有 Web 读数全部照旧。
- 不必把 Decision join 进分桶热路径。
- 代价是同一事实存两份（Decision 一侧、Question 一侧）。

**四、不跟随。**
事后改 Decision 的领域，**不**回溯改写已挂 Question 的标签。历史样本按**当时**的口径解释——与 ADR-0020 处理清单条目版本是同一条理由：允许"顺手重标"就等于允许历史被无声改写，而**不会有任何用例失败**。

**五、改写历史归属必须显式且留痕。**
唯一能重写已挂 Question 标签的路径是一条显式命令（`retag-decision`），必须带理由，并按 [ADR-0012](./0012-revisions-must-leave-a-trace.md) 留痕。

**六、两份数据之间允许差异，且差异只由显式动作产生。**
默认路径下两者一致；`retag-decision` 之后两者在"当时 vs 现在"的意义上不一致——这是设计要的。不做自动修复、不做后台对齐。一致性由测试保证（传播确实发生、事后改 Decision 不污染历史），不由运行时不变量保证。

**七、词汇由用户掌握，agent 只能提议。**
`--tags` 里出现库里没有的词 ⇒ **大声失败**（`NOT_FOUND` + 指引文案），绝不静默新建。用户确认后由 `add-domain` 立起这个词。理由是分桶曲线的样本量约束：允许自动造词，一个月后会得到 30 个领域各 1–2 条样本——那时曲线不是"不准"，而是**永远拟合不出来**，且这个失败是静默的。

**八、未标领域允许为空，但必须可见、可补。**
必填会挡住"我还没想清楚"这条诚实路径（与 ADR-0011 允许未量化预测同一条理由：逼出来的东西比没有更糟）。因此：未标领域能被列出来（`list-untagged-decisions`）并在到期提醒里带一行计数。**不允许任何 `未分类`/`unclassified` 兜底标签**——它会变成一个装下所有东西的桶，看起来像数据，实际是垃圾，还会污染分桶信噪比。

**九、补齐缺失 ≠ 重标。**
给一条**从未标过**领域的决策补标时，对新挂的和**已挂的** Question 一并写入（因为本来就缺，不是改写）。只有改一条**已标过**的决策（四、五）才是重标，必须走显式 `retag-decision` 并留痕。

**十、标签是路径式的，而且允许多值。**
一条决策可以挂多个标签（交叉与否由打标签的人自己判断），标签本身用层级路径表达，例如 `投资/宏观/CPI`。机制上不需要新表：`Tag.name` 就是一个路径字符串。

**十一、前缀命中包含后代。**
查 `投资/宏观` 会命中 `投资/宏观/CPI`（与 Obsidian 同行为）。这是想要的方向：宽检索一次命中。代价是父子桶**重叠**，因此层级之间的读数**不是**彼此独立的桶。

**十二、路径式标签的书写规则与判重。**
合法字符沿用 Obsidian：字母、数字、`_`、`-`、`/`（层级分隔）、Unicode（含中文）；**不允许空格**；必须含至少一个非数字字符。**显示保留原样，但折叠判重**：`CPI` 仍显示为 `CPI`，唯一性按 `lower(name)` 判。

- 库里现状是 `@@unique([name, userId])`，**大小写敏感**——不加处理时 `CPI` 与 `cpi` 会裂成两个桶，而这类错误是静默的（Obsidian 把二者视为同一个标签，我们跟随）。
- 实现：加一列 `nameNormalized`，唯一约束改成 `@@unique([nameNormalized, userId])`，一次迁移。

**十三、判据按显式前缀计算。**
`domain-report --prefix 投资/宏观`：**前缀即领域**，粗细由用户选。报告必须注明"此读数包含其子标签的条目"——否则宽口径会被误读成细分口径。

- 不做"自动选最细且样本足够的层级"：读数会随样本增长**悄悄换口径**，上个月的结论与这个月不可比。
- 不默认展示全部前缀：重叠的解释责任不应该默不作声地推给读者。
- 单个前缀的读数本身就是完整答案；本 ADR 不要求把层级呈现为可比较的并列项。

**十四、标签 CRUD 的开放边界。**

- **读**（`list-domains`、按前缀检索）：对 agent 完全开放。
- **新建**：接口同样可被 agent 调用，但调用前**必须先取得用户确认**（与第七节一致）。原因是失败模式静默：agent "顺手"造的词会让每个桶只剩 1–2 条样本，判据永远不会显示，而这件事不会有任何报错。

**十五、改名给出口但强制理由，删除只在零引用时允许。**

- `rename-domain --from 投资/宏观/CPI --to 投资/宏观/物价 --reason "…"`：一次性重写所有引用，按 ADR-0012 留痕；命令输出必须**显式报出这次改名动了多少条历史归属**。
- 删除只允许**零引用**的标签。已被引用的标签不删——删它就是静默改写历史归属（第四节）。
- 这两条都是同一件事的两种情形：**用过的标签属于历史**。能改，但改的动作要被看见；不能删，因为删除没有留痕的位置。

## Considered Options

- **只标 Question，不引入 `Decision.tags`**：改动最小 → 但"一次决策"要打多次标签，漏打会静默改变分桶样本，且**用户的心智单位没有落点**。
- **只标 Decision，改分桶查询去 join Decision**：单一事实来源 → 但同时改热路径、并绕开上游 `Tag` 机制（TrackRecord 一类读数失效）。
- **让 Question 标签跟随 Decision 变化（派生）**：永远一致 → 但历史会被后来的重标改写，重标变成无声动作；分桶查询也要走派生路径。
- **引入独立的"领域"表**：术语更干净 → 但 `Tag` 已经满足需求（按 user 唯一、可多值），多一张表只是多一份需要同步的概念。领域与标签的差别是**语言**上的，不是**结构**上的。

## Consequences

- **schema**：`Decision.tags Tag[]`（与既有 `Tag.questions` 并列的隐式多对多），一次迁移，**无数据回填**（存量决策视为未标领域）。
- **CLI**：`create-decision` / `retag-decision` 接受 `--tags`；未知领域**大声失败**（见七），新词由 `add-domain` 立起。另有 `list-untagged-decisions`（见八）。
- **Web**：打标签是用户可操作的能力，按 AGENTS.md §8 两边都要有，落在票据 09–11 的 Web 写入口。
- **skill**：捕获时问一次领域，**不自己造词**。
- **测试**：一条自证用例证明"挂接时传播发生"，一条证明"事后改 Decision 不污染已挂样本"（去掉守卫即变红）。
- **未标领域的决策必须可见**：能被列出来并补标。否则复盘时"没打标签"与"没有这条决策"无法区分。
- **迁移**：`nameNormalized` 列 + 唯一约束改为 `@@unique([nameNormalized, userId])`（见十二）。
- **报告**：按前缀出读数，并注明包含子标签（见十三）。
