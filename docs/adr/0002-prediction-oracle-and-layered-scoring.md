# Prediction 按结算判据分类，计分分层

每个 `Prediction` 必须声明其**结算判据（Resolution Oracle）**类型：**公共事实**、**Agent 可观测**、或**自我报告**。

判据类型决定计分口径：三类**都可以**进入**个人纵向校准**（校准的本质是"你 vs 你的过去"，不需要他人参与）；但只有**公共事实**类进入**相对分 / 排行榜**（相对分要求同一个问题上存在多个预测者，而他人无法对当事人的自评或私人体感下注）。

我们拒绝 ① 一视同仁——自评类会污染排行榜；也拒绝 ③ 完全隔离自评类——那会丢掉当事人最在乎的信号。自评类另有一条硬约束：**评分锚点必须在决策时冻结**，否则结算会退化为对记忆的测量（见 Resolution Drift）。

## Considered Options

- **① 不区分**：所有 Prediction 混入同一 Brier / 相对分 → 自评类污染社交比较口径。
- **③ 完全隔离**：自评类不计分，只作定性输入 → 丢掉最有价值的校准信号。

## Consequences

- `Prediction` 需要一个"结算判据类型"字段。
- 评估层分裂为两个口径：个人纵向校准（全类型）与相对分（仅公共事实）。
- 自评类在记录时必须同时冻结评分锚点。
- 落地形态：非公共事实类的 `QuestionScore.relativeScore` 写 `null`（读侧一律以 `null` 为"不参与相对分"），排名改按绝对分（`lib/_scoring.ts` 的 `dropRelativeScores`）；资格判定单点定义在 `lib/web/calibration.ts`。
