# 保留人类操作的写入口，并为每条记录标注录入来源

Web UI / TUI 上**人类直接操作**的交互是最终、最可信、最兜底的输入源，因此必须保留创建、编辑与结算的写能力。Agent 是**并行的加速入口，不是替代品**——把最可信的输入源关掉去换低摩擦，是把优先次序搞反了。

同时，凡由 Agent 创建或整理的记录，**必须在记录时标注录入来源**：是 **Agent 自主搜集**，还是 **依据人的明确指令**。理由是不对称的：人工直录的内容天然是人的原始表达，而 Agent 自行搜集的数字可能**从未被人逐字背书**——若不区分，校准数据里就会混入"用户从未真正认同过的概率"，而那正是校准要测的东西。

## Considered Options

- **① Web 完全只读**：关掉最可信的输入源，且提案确认必须先找 pi 对话。
- **③ / ④ 只读 + 提案收件箱 / 可创建不可编辑**：人为缩小了人类可操作的表面，与"人工交互是最可信兜底"直接冲突。

## Consequences

- Web 保留写能力（本 ADR 明确否决此前推荐的 ① / ③ / ④）。
- 记录需携带"录入来源"字段。
- 人工手动结算与 ADR-0004 的分层授权并不冲突：人工操作本身就是最高授权。
- 未经背书的 Agent 搜集记录不得进入校准（见 [ADR-0008](./0008-endorsement-required-for-agent-collected.md)）。
