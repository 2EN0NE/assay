# 审计元数据落库：只存标识，不存会话正文

记录落库时一并写入**调用上下文**：发起方类别（人 / 代理，取自 [ADR-0024](./0024-provenance-default-by-context.md) 的标记与声明）、pi 会话标识（`PI_SESSION_ID`）、时间。用途是让"这条记录自称是人给的，但它来自哪个会话、当时问过没有"事后**可对质**——否则 ADR-0024 的默认方向就只是一次不可复查的自我申报。

**只存标识，不存会话正文。** 正文在 pi 的会话文件里（`PI_SESSION_FILE`）；一旦复制进库，容量、隐私与清理责任会一起进来，而审计只需要能定位到那个会话。

## 容量

实测本库 **9.5 MB** 就装下了整份 schema（80 User / 84 Question / 68 Forecast / 16 Decision / 10 Revision / 110 Notification），`Forecast` 表含索引共 64 kB / 68 行。

新增字段每行不过数十字节（会话标识约 40 B + 类别 + 时间）。一个人的记录量在 `10^4`～`10^5` 行级，即**几 MB**；要逼近 100 MB，需要百万行级的 Forecast/Revision。**所以 100 MB 不是需要担心的约束——需要守的是"只存标识、不存正文"。**

## Consequences

- 迁移只加列，不动既有语义。审计信息**不是权威**，只是可对质的线索（ADR-0024）。
- 审计字段谁有权读、共享题上是否可见，属于可见性语义（决策树 B 分支），尚未裁决。
- 有了它，"来自 pi 会话却自称数字由当事人给出"这类记录可以被筛出来复查——这是把 ADR-0024 的默认方向变成可验证承诺的前提。
