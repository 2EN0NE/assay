# 已冻结的字段可改，但必留痕；首次 Forecast 之前例外

对已冻结字段（结算判据、期限、评分锚点）的修改**允许发生**，但每一次都必须留下**修订记录**：旧值、新值、时间、理由，并在复盘视图中可见（`R` = ②）。唯一例外：**首次 `Forecast` 之前**的改动不计为修订——那时还没有任何信念被记录，改动无漂移可言，纯粹是修文字。

为什么不禁止：跟踪 Agent 跑在**独立上下文**（ADR-0003），它**没有任何途径**回头问当事人"你当初想写的是三还是一"。若判据写死了错的、或存在歧义，这条预测就**永久不可结算**——代价落在可用性上，而不是纯洁性上。

为什么不选"结算前放开"：**越接近到期，当事人越有动机把判据改得对自己有利**（结果已经隐约可见）。把最危险的窗口设为自由窗口，等于把 Resolution Drift 制度化。

留痕之所以够用：Resolution Drift 的杀伤力来自**无声**。一旦"我改过判据"被记录下来，它本身就成了复盘材料——与 `Unquantified`（ADR-0011）让"逃避量化"可见，是同一个机制。

**同一机制后来扩到 Decision 的叙事字段。** 决策叙事（陈述 / 理由 / 预期后果 / 当时已知 / 当时未知）在清单锁定后**仍可写**（ADR-0020：叙事不计分，事后补充不产生激励扭曲），但**改写已填写的内容必须带理由并留痕**。理由与本 ADR 完全一致：多写手是真的——CLI 由 agent 驱动（ADR-0007），无痕改写意味着"当事人写下的记录可以被别人改掉而当事人不知道"。**给空白字段补写不受此限**：那不是改写，而是当初就没记。

## Considered Options

- **① 完全不可改**：把错别字与歧义一起锁死，代价是大量预测永久无法结算。
- **③ 结算前可改**：把最危险的窗口（临到期）放开。

## Consequences

- 需要一张修订记录（`Revision`）：字段、旧值、新值、时间、理由。
- 同一张表同时承载 **Decision 叙事字段**的改写（ADR-0020）：`Revision` 的主体因此既可能是 Question（冻结字段）也可能是 Decision（叙事字段），用 `questionId` / `decisionId` 二者恰有其一表达。
- 修订必须在复盘视图中可见，否则留痕没有意义。
- "首次 `Forecast` 之前"必须是一个**可判定**的时点。
- "理由"是**强制**的：变更已冻结字段（并因而产生修订）却未给出理由时，`editQuestion` 直接拒绝（`lib/web/revisions.ts` 的 `missingRevisionReason`）。
- 快照 → 留痕 → 更新必须同事务（`prisma.$transaction`），否则更新失败会留下并未发生的修订。
