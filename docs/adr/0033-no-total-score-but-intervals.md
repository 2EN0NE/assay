# 不给总分，但读数必须带不确定性区间

ADR-0032（R4）定了判据是"相对领域基准率的技能分"，R5 决定要不要在此之上再给一个"总分"。

**一、不给总分。**
分数的第一用途是**比较**：与他人比、与自己过去比、拿来设目标。单人单领域场景里没有可比对象，剩下的唯一用途就是"优化那个数"。而且一个总分必然把过程完成度与结果水平压成同一个数（ADR-0002 明确分层）。

**二、但"不给总分"不等于"只给符号"。**
方向（正/负）不足以回答"我的水平如何"——还要回答**差多少**。因此技能分以 **数值 + 不确定性区间**呈现，而不是一个箭头。

**三、区间用配对 bootstrap 算，不用正态近似。**
对该领域已结算的题做**有放回重采样**，每次重算技能分，取分位数（默认 95%）。

- 不假设正态：Brier 相关统计量在小样本下明显偏斜，正态近似会给出过窄的区间——**过窄的区间比没有区间更危险**。
- 不引入先验：贝叶斯后验需要先验分布，而那会把主观输入放回判据里（违反 ADR-0032 五）。
- 随机性必须**可复现**：固定随机种子，且同数据必得同结论。这与本仓库"门禁只能整片变红、不许偶发变红"的口径一致（`retries: 0`）。

**四、"统计学上有意义"落地成可检查的呈现规则。**

| 区间相对 0 | 允许的表述                                      |
| ---------- | ----------------------------------------------- |
| 不跨 0     | "显著优于基准" / "显著劣于基准"                 |
| 跨 0       | **"无法判断方向"**——不许把 +0.03 说成"略有提升" |

样本不足（`N < 20`，见 ADR-0032 四）时不给技能分，只给样本数与悬空计数。

**五、量级必须可解释：三个数一起给。**

1. 你的 Brier
2. 参照（常数基准率）的 Brier
3. 技能分 + 区间

缺任一项，量级都无法被外人复核——只给技能分等于给一个没有分母的比值。

**六、不得隐藏不确定性。**
只给点估计是伪精度；把区间放在 JSON 里而呈现层不提是同一件事。呈现层的每个技能分旁边必须有区间，且当区间跨 0 时，文案不得使用趋势性措辞。

## Considered Options

- **点估计作为唯一读数**：最简洁 → 伪精度；小样本下 +0.03 与 +0.2 的差别常被区间噪声吞没。
- **正态近似区间**：实现一行 → 小样本下区间过窄，会系统性地把"无法判断"说成"显著"。
- **贝叶斯后验**：理论上更优雅 → 需要先验，等于把主观输入放回判据。
- **只给符号（正/负/约等于 0）**：最不容易被误解 → 但答不出"差多少"，而"多少"正是用户要问的。
- **给一个总分**：见一。

## Consequences

- **实现**：一个纯函数的 bootstrap（现有 JS 即可，**不新增依赖**）+ 固定种子；落在结果读数一侧，不进聚合热路径。
- **CLI**：`domain-report` 输出 `skillScore` / `ci` / `brier` / `brierRef` / `n` / `pending` / `verdict`（`better` / `worse` / `inconclusive`）。
- **Web**：同四件读数 + 区间，`verdict` 用同样的三态文案（AGENTS.md §8 对等）。
- **测试**：常数押注 ⇒ 技能分 0 且区间跨 0（自证：去掉基准率参照即变红）；固定种子下两次运行结果逐位相同（防 flaky）；区间跨 0 时文案不含趋势词。
- **阈值与种子**是代码常量（ADR-0020 同精神），不是用户数据。
