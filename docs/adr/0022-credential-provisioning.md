# 凭据发放：CLI 自举建号，Web 负责轮换

CLI 增加 `init`：在库中创建一个身份、打印它的凭据，**不需要邮件、不需要浏览器**。Web 侧的 `/api-setup`（`regenerateApiKey`）保持不变，负责查看与轮换。两者都只是把**已经存在**的能力暴露出来——建号是一行 insert，凭据的生成与轮换 procedure 早已实现。

这拆掉了「开箱即用的第一道墙」：一个空库加一把钥匙就能开始记录，不再需要先走一遍邮件登录。

## Consequences

- `init` 等于**自助注册**。护栏口径**尚未决定**：候选是"只允许在空库时建号"，或"必须显式带 `--allow-create-user`"。
- 凭据一旦就是身份（[ADR-0021](./0021-cli-identity-by-credential.md)），`init` 打印出来的**就是身份本身**：输出不得进入日志，且必须能轮换（Web 侧已有此能力）。
- `User.email` 仍是必填且唯一字段，因此 `init` 必须给出一个占位标识（例如由 `--label` 生成）。**身份可以没有真实邮箱**，这条会反过来影响 CONTEXT.md 里"凭据"与"身份"的措辞。
- skill 与 README 需同步：记录一条决策的最小前置从「先登录建号」变为「先 `init` 或先取得钥匙」。
