### Key Decisions

- Decision: 相对分资格的判定也放进 `lib/web/calibration.ts`（与校准排除同一处，AGENTS.md 已写明）
- Rationale: 读侧（SQL `AVG` 忽略 null、聚合处 `!== null`）本来就把 null 当"不参与"，因此**写侧写 null 即完成读侧口径**，不需要改任何聚合——也避免了"新聚合忘过滤"的复发

- Decision: stdout 守卫放在 CLI 边界而非各模块
- Rationale: 让"谁写了 stdout"在发生的当下暴露，而不是变成下游 `JSON.parse` 的神秘失败；npm 横幅与 `console.log` 已经各漏过一次

### Lessons Learned

- **真库验证才抓得到 stdout 污染**：单测里 `console.log` 无害，`list-due`（只读）也看不到问题——只有跑 `settle` / `endorse` 这类会进计分路径的写命令才暴露。作者的"真库验证 stdout 为纯 JSON"当初只覆盖了只读命令
- `npm run` 会把脚本横幅写进 stdout（实测 3 行）；`npm run --silent` 或 `npx tsx` 才是纯的
- `notifications.tsx` 里有一个**名为 `log` 的布尔参数**，因此把 `console.log` 改道时要用别名导入（`log as logToStderr`）
- pi-lens 的 TS server 对 `@prisma/client` 的陈旧快照在此环境里非常顽固：`prisma generate`、`touch` 生成产物、删 `tsconfig.tsbuildinfo` 均无效（它只重读 project 文件）。判据仍是 AGENTS.md 那三条，**重启语言服务器**才能清
- 校验迁移集合与 schema 是否一致，shadow 库比本地库更硬：`prisma migrate diff --from-migrations --to-schema-datamodel --shadow-database-url` 输出空迁移才算过
